## 프로젝트 개요
---
### 한 줄 정의
Git 저장소의 브랜치 차이와 커밋 맥락을 기반으로 Claude 또는 Codex를 선택해 코드리뷰를 실행하고, 리뷰 과정과 결과를 웹 대시보드에서 통합 관리하는 개발자용 코드리뷰 플랫폼이다. Next.js를 웹 애플리케이션으로 사용하고 PocketBase에 사용자, 저장소, 리뷰 요청, diff, 대화, 결과를 저장한다.

### 제품 목표
개발자가 웹에서 리뷰를 수동으로 신청하면 현재 브랜치와 타깃 브랜치의 diff 및 선택된 커밋 맥락을 기준으로 일관된 AI 코드리뷰를 빠르게 수행하도록 한다. 리뷰 요청부터 진행 상태, 지적사항, 토론, 해결 여부, 과거 기록까지 중앙화하여 팀의 코드 품질 관리와 개발자 학습을 지원한다.

### 배경
현재 개발팀은 코드리뷰를 수동으로 준비하고 여러 도구에서 결과를 확인해야 하므로 리뷰 부담이 크고 피드백이 늦다. 리뷰 기준과 품질이 리뷰어마다 달라질 수 있으며, 커밋·diff·논의·해결 이력이 분산되어 과거 지식을 재활용하기 어렵다. 초기 버전은 웹에서 리뷰를 수동 신청하고, 사용자가 로컬에서 이용 가능한 Claude 또는 Codex 구독 환경을 선택해 리뷰를 실행하는 방식으로 범위를 제한한다.

### 사용자 문제
개발자는 코드 변경사항을 리뷰받기 위해 diff를 추출하고 맥락을 정리하며 결과를 별도 문서나 대화 도구에 기록해야 한다. 이 과정은 반복적인 수작업을 유발하고, 리뷰 피드백이 늦거나 일관되지 않으며, 저장소·커밋·논의 이력이 흩어지는 문제를 만든다. 팀 관리자는 리뷰 진행 상황과 반복적으로 발생하는 품질 이슈를 한곳에서 추적하기 어렵다.

### 해결 방안
사용자가 저장소, 현재 브랜치, 타깃 브랜치, 리뷰 대상 커밋과 AI 모델을 웹에서 지정하면 시스템이 두 브랜치의 diff와 커밋 맥락을 바탕으로 리뷰를 실행한다. 리뷰 진행 상태와 결과를 PocketBase에 저장하고, 파일·라인 단위의 지적사항, 심각도, 설명, 개선 제안, 사용자 토론 및 해결 상태를 웹 대시보드에서 제공한다. 리뷰 결과는 저장소와 커밋에 연결되어 이후 검색과 학습에 활용할 수 있다.

### 차별점
단순한 AI 코드 생성 도구가 아니라 저장소의 브랜치 비교를 중심으로 리뷰 요청부터 결과와 토론까지 전체 과정을 추적하는 데 초점을 둔다. Claude와 Codex 중 사용자가 자신의 로컬 구독 환경에 맞는 모델을 선택할 수 있으며, 모델 선택과 리뷰 실행 이력을 함께 보존한다. diff만 보는 기본 리뷰와 커밋·저장소·기존 논의 맥락을 활용하는 확장 리뷰를 동일한 기록 체계 안에서 관리한다.

### 타겟 사용자
주요 사용자는 Git 브랜치 기반으로 개발하는 소규모 팀과 엔터프라이즈 개발팀의 개발자, 테크 리드, 코드리뷰 담당자이다. 개발자는 풀 리퀘스트를 생성하기 전후에 자신의 변경사항을 빠르게 사전 점검하거나 팀 리뷰를 보완하려고 사용한다. 테크 리드와 팀 관리자는 리뷰 요청의 진행 상태, 반복 이슈, 과거 리뷰 결과를 확인하고 팀의 코드 품질과 개발자 학습을 지원하려고 사용한다. 사용자는 Git 저장소와 브랜치 구조를 이해하고, 선택한 Claude 또는 Codex의 로컬 구독 실행 환경에 접근할 수 있어야 한다.

### 사용자 시나리오
개발자가 로컬에서 기능 브랜치의 코드를 수정하고 커밋한 뒤 웹 대시보드에 로그인한다. 사용자는 저장소와 현재 브랜치, 타깃 브랜치, 리뷰에 포함할 커밋 또는 변경 범위, 리뷰 맥락, Claude 또는 Codex 모델을 선택해 리뷰를 신청한다. 시스템은 두 브랜치의 diff를 생성하거나 전달받고 선택된 실행 환경에서 리뷰를 수행하면서 상태와 로그를 저장한다. 사용자는 대시보드에서 파일 및 라인별 리뷰 결과를 확인하고, 항목에 댓글을 남기며, 수정 완료 또는 보류 상태를 관리한다. 팀 구성원은 동일한 저장소와 브랜치의 리뷰 이력을 조회해 이전 지적사항과 논의 내용을 참고한다.

### 핵심 지표
리뷰 신청에서 첫 결과 확인까지의 평균 소요 시간, 리뷰 요청 완료율, 리뷰 결과 조회율, 리뷰 결과에 대한 사용자 해결·확인 처리율, 리뷰 요청당 수작업 준비 단계 수, 리뷰 이력 재조회율을 측정한다. 사용자별 주간 활성 리뷰 요청자 수와 팀별 월간 반복 사용률을 초기 제품 적합성 지표로 사용한다. 리뷰 결과의 중복·무관 지적 비율, 사용자 피드백 기반 유용성 평가, 모델별 성공률과 평균 실행 시간도 함께 추적한다.

### 리스크
로컬 Claude 또는 Codex 구독 환경의 인증 방식과 실행 가능 범위가 사용자 환경마다 달라 안정적인 자동 실행이 어려울 수 있다. 민감한 소스 코드와 리뷰 결과가 PocketBase에 저장되므로 접근 제어, 암호화, 보존 기간, 로그 내 비밀정보 노출을 명확히 설계해야 한다. AI 리뷰가 잘못된 지적이나 누락을 만들 수 있으므로 결과를 자동 승인이나 배포 판단으로 사용하지 않고 사용자가 확인하는 보조 도구로 정의해야 한다. 대규모 저장소와 긴 diff는 처리 시간, 비용, 컨텍스트 한도, 브라우저 성능 문제를 유발할 수 있다. Git 인증, 브랜치 변경, 중복 요청, 네트워크 단절에 대한 복구 정책이 초기 범위에서 불명확할 수 있다.
