## 1. 저장소 및 브랜치 리뷰 대상 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

사용자는 리뷰할 Git 저장소와 현재 브랜치, 타깃 브랜치를 등록하고 리뷰 범위를 구성할 수 있어야 한다. 시스템은 선택된 브랜치 간 diff와 선택된 커밋 맥락을 리뷰 요청의 기준 데이터로 관리한다. 초기 범위는 지원 가능한 Git 저장소와 브랜치 기반 변경사항에 한정하며, 자동 풀 리퀘스트 생성이나 임의의 외부 저장소 동기화는 포함하지 않는다.

**수용 기준:**
```
1. ○ 사용자가 저장소, 현재 브랜치, 타깃 브랜치를 선택하거나 입력해 리뷰 대상 구성을 저장할 수 있다.
2. ○ 현재 브랜치와 타깃 브랜치가 동일하면 리뷰 신청을 차단하고 변경된 브랜치를 선택하도록 안내한다.
3. ○ 시스템이 두 브랜치의 변경 파일, 추가·삭제 라인, 커밋 식별자를 리뷰 요청과 연결한다.
4. ○ 커밋이 없거나 diff가 비어 있는 경우 리뷰 신청을 차단하고 원인을 사용자에게 표시한다.
5. ○ 저장소와 브랜치 정보에 접근할 수 없는 경우 리뷰 요청을 생성하지 않고 권한 또는 동기화 오류를 표시한다.
```


### 1.1 저장소와 브랜치 선택
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 개발자, 코드리뷰어, 테크 리드 | **기기**: 데스크톱 웹 브라우저, 노트북 웹 브라우저

**기능의 근거**: 개발자가 diff를 직접 추출하고 리뷰 맥락을 정리하는 반복 작업을 줄이기 위해 필요하다.

개발자는 접근 권한이 있는 Git 저장소에서 현재 브랜치와 타깃 브랜치를 선택하여 리뷰 대상을 구성한다. 시스템은 선택 정보를 검증하고 리뷰 요청에 재사용할 수 있도록 저장한다. 임의 외부 저장소 동기화와 자동 풀 리퀘스트 생성은 포함하지 않는다.

**성공 기준**: 리뷰 요청당 수작업 준비 단계 수가 감소한다.

**개발 준비 슬롯**
- **선행조건**: - 사용자는 대상 팀과 저장소에 접근 권한을 보유한다.
- **트리거**: - 사용자가 리뷰 요청 작성 화면을 연다.
- **동작**: - 시스템은 접근 가능한 저장소와 해당 브랜치 선택 정보를 제공하고 선택값을 검증한다.
- **결과**: - 선택한 저장소와 현재 브랜치 및 타깃 브랜치가 리뷰 대상 구성에 저장된다.
- **예외**:
  - 저장소 또는 브랜치에 접근할 수 없으면 구성을 저장하지 않고 권한 또는 동기화 오류를 표시한다.
  - 현재 브랜치와 타깃 브랜치가 같으면 다음 단계 진행을 차단한다.
- **표시**: - 저장소와 두 브랜치 선택 필드 및 검증 오류를 화면에 표시한다.
- **권한 & 접근**: - 권한이 없는 저장소는 선택 목록과 API 응답에서 제외한다.
- **비즈니스 규칙**: - 리뷰 대상의 현재 브랜치와 타깃 브랜치는 서로 달라야 한다.
- **데이터**: - 리뷰 대상 구성은 저장소 식별자, 현재 브랜치명, 타깃 브랜치명을 참조한다.


### 1.2 브랜치 diff와 커밋 맥락 수집
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 개발자, 코드리뷰어, 테크 리드 | **기기**: 데스크톱 웹 브라우저, 노트북 웹 브라우저, 로컬 개발 환경, 서버 또는 자체 호스팅 실행 환경

**기능의 근거**: 일관된 AI 리뷰를 위해 브랜치 차이와 커밋 맥락을 요청 기록에 중앙화해야 한다.

시스템은 선택된 두 브랜치의 변경 파일, 추가·삭제 라인, 커밋 식별자와 선택된 커밋 맥락을 수집하여 리뷰 요청의 기준 데이터로 연결한다. 변경사항이 없는 요청은 생성하지 않는다. 코드 변경을 자동 수정하거나 병합하는 기능은 포함하지 않는다.

**성공 기준**: 리뷰 신청에서 첫 결과 확인까지의 평균 소요 시간이 감소한다.

**개발 준비 슬롯**
- **선행조건**: - 유효한 저장소와 서로 다른 두 브랜치가 선택되어야 한다.
- **트리거**: - 사용자가 리뷰 대상 구성을 검증하거나 리뷰 요청을 제출한다.
- **동작**: - 시스템은 두 브랜치 간 diff와 관련 커밋 식별자를 수집하여 요청 입력으로 연결한다.
- **결과**: - 변경 파일과 추가·삭제 라인 및 커밋 맥락이 리뷰 요청에 연결된다.
- **예외**: - 커밋이 없거나 diff가 비어 있으면 리뷰 요청 생성을 차단한다.
- **표시**: - 수집된 변경 요약 또는 수집 실패 원인을 사용자에게 표시한다.
- **권한 & 접근**: - 사용자는 접근이 허용된 저장소의 diff만 수집할 수 있다.
- **비즈니스 규칙**: - diff는 선택한 현재 브랜치와 타깃 브랜치의 비교 결과를 기준으로 한다.
- **데이터**: - 리뷰 요청은 변경 파일 목록, 라인 증감 정보, 커밋 식별자 및 diff 데이터를 연결해 저장한다.

## 2. 웹 기반 리뷰 요청 및 모델 선택
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

사용자는 웹 대시보드에서 리뷰 요청을 수동으로 생성하고 리뷰 대상, 추가 맥락, 리뷰 범위, 실행할 AI 모델을 지정할 수 있어야 한다. 모델 선택지는 Claude와 Codex로 제공하며, 실제 실행은 사용자가 접근 가능한 로컬 구독 실행 환경을 사용한다. 시스템은 요청 당시의 모델, 입력 범위, 사용자 입력을 리뷰 기록에 보존한다.

**수용 기준:**
```
1. ○ 로그인한 사용자가 리뷰 요청 작성 화면에서 저장소, 브랜치, 커밋 범위, 리뷰 맥락, 모델을 선택할 수 있다.
2. ○ Claude와 Codex 중 하나를 선택하지 않으면 리뷰 요청 제출을 허용하지 않는다.
3. ○ 리뷰 요청 제출 후 고유한 리뷰 요청이 생성되고 대기 또는 실행 준비 상태로 표시된다.
4. ○ 중복 제출이나 버튼 연타가 발생해도 동일한 요청이 의도하지 않게 여러 번 생성되지 않는다.
5. ○ 생성된 리뷰 요청에 요청자, 생성 시각, 저장소, 브랜치, 커밋, 모델, 상태가 저장된다.
```


### 2.1 리뷰 요청 작성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 개발자, 코드리뷰어, 테크 리드 | **기기**: 데스크톱 웹 브라우저, 노트북 웹 브라우저

**기능의 근거**: 리뷰 준비 정보가 여러 도구에 흩어지는 문제를 줄이고 요청 과정을 중앙화하기 위해 필요하다.

로그인한 개발자는 웹에서 저장소, 브랜치, 커밋 범위와 추가 리뷰 맥락을 입력해 수동 리뷰 요청을 작성한다. 시스템은 요청 당시의 입력과 요청자 및 생성 시각을 보존한다. 자동 리뷰 신청은 초기 범위에 포함하지 않는다.

**성공 기준**: 리뷰 요청 완료율이 증가한다.

**개발 준비 슬롯**
- **선행조건**: - 사용자는 로그인하고 선택한 저장소에 리뷰 생성 권한을 보유한다.
- **트리거**: - 사용자가 새 리뷰 요청 작성을 선택한다.
- **동작**: - 시스템은 대상 구성과 커밋 범위 및 추가 맥락을 입력받아 유효성을 검증한다.
- **결과**: - 유효한 입력으로 고유한 리뷰 요청 초안 또는 대기 요청이 생성된다.
- **예외**: - 동일한 제출이 반복되면 하나의 요청만 생성한다.
- **표시**: - 요청 작성 양식과 필수 입력 오류 및 생성 결과를 표시한다.
- **권한 & 접근**: - 비로그인 사용자와 권한 없는 사용자의 요청 생성 API 호출을 거부한다.
- **비즈니스 규칙**: - 리뷰 요청은 유효한 저장소·브랜치·변경 범위를 포함해야 한다.
- **데이터**: - 리뷰 요청은 요청자, 생성 시각, 저장소, 브랜치, 커밋 범위, 추가 맥락, 상태를 저장한다.


### 2.2 AI 모델 선택

**기능의 근거**: 사용자가 자신의 로컬 구독 환경에 맞는 모델을 선택하고 모델별 리뷰 이력을 비교할 수 있어야 한다.

개발자는 리뷰 요청마다 Claude 또는 Codex 중 자신의 로컬 구독 실행 환경에서 사용할 AI 모델을 선택한다. 시스템은 선택 모델을 요청과 실행 이력에 보존한다. 모델 자동 선택과 별도 유료 API 과금은 포함하지 않는다.

**성공 기준**: 모델별 성공률과 평균 실행 시간을 측정한다.

**개발 준비 슬롯**
- **선행조건**: - 사용자는 리뷰 요청 작성 화면에 진입해야 한다.
- **트리거**: - 사용자가 모델 선택 필드를 연다.
- **동작**: - 시스템은 Claude와 Codex 선택지를 제공하고 선택값을 요청에 반영한다.
- **결과**: - 선택한 모델이 리뷰 요청과 이후 실행 기록에 저장된다.
- **예외**: - 모델을 선택하지 않으면 리뷰 요청 제출을 차단한다.
- **표시**: - 모델 선택지와 선택 필수 안내를 표시한다.
- **권한 & 접근**: - 리뷰 생성 권한이 있는 사용자만 모델을 선택해 요청을 제출할 수 있다.
- **비즈니스 규칙**: - 초기 버전의 선택 가능한 모델은 Claude와 Codex로 제한한다.
- **데이터**: - 리뷰 요청은 선택 모델 값을 필수로 저장한다.

## 3. 로컬 AI 리뷰 실행 및 진행 상태 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

시스템은 리뷰 요청의 diff와 선택된 맥락을 해당 모델의 로컬 구독 실행 환경에 전달하고 결과를 회수해야 한다. 리뷰 실행은 대기, 실행 중, 완료, 실패, 취소와 같은 상태로 관리하며 사용자가 웹에서 진행 상황을 확인할 수 있어야 한다. 초기 버전은 Claude 또는 Codex의 로컬 실행 연동 방식을 지원하되, 별도 유료 API 과금 모델이나 모델 자동 선택은 포함하지 않는다.

**수용 기준:**
```
1. ○ 리뷰 요청이 실행 대기, 실행 중, 완료 또는 실패 상태로 전이되고 현재 상태가 대시보드에 표시된다.
2. ○ 사용자가 선택한 모델과 연결된 로컬 실행 환경으로 리뷰 입력이 전달된다.
3. ○ 리뷰 실행 중 새로고침하거나 다른 화면으로 이동해도 상태와 결과가 서버에 보존된다.
4. ○ 로컬 실행 환경이 없거나 인증되지 않았거나 응답하지 않으면 요청을 실패 상태로 전환하고 재시도 가능한 오류를 표시한다.
5. ○ 동일한 리뷰 요청의 중복 실행을 방지하고, 실행 시작·완료·실패 시각과 오류 정보를 저장한다.
```


### 3.1 로컬 AI 리뷰 실행

**수용 기준:**
```
1. ○ 완료된 리뷰에 전체 요약과 파일별 또는 라인별 리뷰 이슈가 표시된다.

5. ○ 리뷰 결과 화면에서 AI의 지적이 자동 승인이나 배포 승인으로 해석되지 않는다는 안내를 제공한다.

## 6. 통합 대시보드 및 리뷰 이력 조회

```

4. ○ 리뷰 상세 화면에서 요청 정보, diff 요약, 실행 상태, 리뷰 결과, 댓글, 이슈 상태를 함께 확인할 수 있다.
5. ○ 데이터가 없는 경우 빈 상태 화면을 표시하고, 조회 실패나 부분 로딩 시 재시도 가능한 안내를 제공한다.

## 7. 사용자 인증 및 팀 접근 권한 관리

시스템은 사용자를 인증하고 팀과 저장소 단위로 리뷰 요청, 소스 코드, 결과, 댓글에 대한 접근을 제한해야 한다. 개발자는 자신이 허용된 팀과 저장소의 리뷰를 생성·조회할 수 있고, 테크 리드와 관리자는 팀 범위의 기록과 진행 상황을 관리할 수 있어야 한다. 초기 권한 모델의 세부 역할과 엔터프라이즈 인증 방식은 실제 팀 운영 정책에 따라 확정하며, 비로그인 사용자의 리뷰 데이터 접근은 허용하지 않는다.

**수용 기준:**
```
1. ○ 비로그인 사용자가 리뷰 대시보드와 리뷰 데이터에 접근하면 로그인 화면으로 이동한다.
2. ○ 사용자는 자신에게 허용된 팀과 저장소의 리뷰만 조회할 수 있다.
3. ○ 권한이 없는 사용자는 리뷰 생성, 결과 조회, 댓글 작성 API를 호출해도 거부된다.
4. ○ 관리자는 팀 구성원과 저장소 접근 권한을 관리할 수 있다.
5. ○ 권한 거부와 인증 만료가 화면과 서버 응답에서 구분되어 처리된다.

- **트리거**:
  - 비로그인 사용자가 보호된 대시보드 또는 리뷰 데이터를 요청한다.
  - 사용자가 로그인 화면에서 인증을 시도한다.
- **동작**: - 시스템은 인증 상태를 검증하고 비로그인 사용자를 로그인 화면으로 이동시킨다.
- **결과**: - 인증된 사용자는 세션으로 보호된 기능에 접근하고 인증 실패 또는 만료 상태는 구분되어 처리된다.
- **예외**: - 인증 만료 시 보호된 요청을 거부하고 재인증이 필요함을 표시한다.
- **표시**: - 로그인 화면과 인증 실패 또는 인증 만료 안내를 구분해 표시한다.
- **권한 & 접근**: - 비로그인 사용자는 리뷰 대시보드와 리뷰 데이터에 접근할 수 없다.
- **비즈니스 규칙**: - 모든 보호 API는 요청마다 인증 상태를 확인한다.
- **데이터**: - 사용자 세션은 사용자 식별자와 인증 상태를 참조한다.

## 8. 리뷰 데이터 보안 및 보존 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

시스템은 리뷰 요청에 포함되는 소스 코드 diff, 커밋 맥락, AI 리뷰 결과, 댓글 및 실행 로그를 민감한 개발 데이터로 취급하고 저장·조회·삭제 전 과정에서 보호해야 한다. 개발자와 팀 관리자는 자신이 접근 권한을 가진 리뷰 데이터의 보존 상태를 확인하고, 적용된 보존 정책에 따라 데이터를 삭제하거나 접근 불가 상태로 전환할 수 있어야 한다. 이 요구사항은 데이터 보호와 수명주기를 다루며, 사용자 인증과 팀·저장소별 접근 허용 판단 자체는 기존 사용자 인증 및 팀 접근 권한 관리 요구사항의 범위로 유지한다.

**수용 기준:**
```
1. ✓ 시스템은 저장된 리뷰 데이터와 실행 로그에서 인증 토큰, 비밀번호, 비밀 키 등 탐지 가능한 민감 정보를 일반 사용자에게 그대로 표시하지 않는다.
